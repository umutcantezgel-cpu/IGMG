# ADR 0011 – E-Mail in Entwicklung, Test und Betrieb

- Status: angenommen · 2026-10-11 · P1 · Bezug: G-02, K-07, K-19, Z-05, Z-11

## Ziel
Keine echte E-Mail verlässt den Rechner (G-02); Tests sehen jede Mail (Z-05: „beide E-Mails im Mail-Fänger“); im Betrieb genügt die Konfiguration eines SMTP-Dienstes.

## Wege
1. **Mailpit** (SMTP 1025, Web/API 8025) als Dienst in docker-compose; App sendet per SMTP.
2. **Datei-Transport** (Nodemailer `streamTransport` → `.eml` in `web/.mail/`).
3. **Fänger im Testprozess** (eigener SMTP-Server im Playwright-Prozess).

## Bewertung
Docker läuft (UMGEBUNG.md) → **Weg 1 als Standard** für Entwicklung und E2E (Mailpit-API `GET /api/v1/messages` lesen die Tests). **Weg 2 als Rückfall** ohne Docker (Variable `MAIL_TRANSPORT=datei`), Tests lesen dann die `.eml`-Dateien. Weg 3 dupliziert Weg 1.

## Festlegungen
- `src/lib/mail/index.ts`: `sendeMail({ an, vorlage, sprache, daten })` → rendert React-Email-Vorlage (`await render()`, HTML + Text) → Transport aus `.env`: `MAIL_TRANSPORT=smtp|datei`, `SMTP_HOST/PORT/USER/PASS/SECURE`, `MAIL_ABSENDER`.
- Versand über Ausgangstabelle (ADR 0005), Wiederholung mit Rückoff; Fehler werden ohne Empfängeradresse protokolliert (K-13).
- Vorlagen `src/lib/mail/vorlagen/*.tsx`, Texte aus `messages` (Namensraum `mail`), drei Sprachen.
- docker-compose: `mailpit` (Image `axllent/mailpit`, MIT) nur im Profil `entwicklung`; im Betrieb wird ein echter SMTP-Dienst eingetragen (M-005).

## Umkehrprobe
Falsch, wenn der Betrieb keinen SMTP-Zugang bekommt. Dann bleibt der Datei-Transport + Hinweis in der Verwaltung („E-Mail-Versand nicht eingerichtet“).

## Folgen zweiter Ordnung
- E2E-Läufe brauchen Mailpit (Docker); ohne Docker laufen sie mit Datei-Transport.
